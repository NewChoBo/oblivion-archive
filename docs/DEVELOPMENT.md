# 챕터 1을 여러 워크트리에서 개발하기

세 엔진의 실행 위치와 공용 데이터는 [루트 안내](../README.md)에 정리했다. 이 문서의 TypeScript 소스, 테스트, 명령 경로는 `babylon/` 기준이다. `shared/`, `asset-sources/`, `public/`은 저장소 루트 기준이다.

아래는 현재 게임의 호출 경로다. 신규 코드의 배치와 멀티플레이·현지화·엔진 이식 단계는 [개발 규칙](../AGENTS.md)과 [구조 설계](ARCHITECTURE-PLAN.md)에 있다.

| 기능              | 구현 위치와 책임                                                                                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 게임 기동         | `src/bootstrap.ts`가 언어를 초기화하고 `src/app/startup.ts`에서 타이틀과 모드 선택을 연다. 레벨에 입장하면 `src/app/main.ts`가 씬과 세션을 연결한다.                                                                                                                           |
| 성채와 챕터       | `src/levels/`에 배치·치수·프리팹을 두고 `src/content/citadel-layout.ts`에서 도면을 해석한다. `src/platform/babylon/citadel/`이 성곽·지구·권양기를 만들고, `chapter/`가 서재·퍼즐·수집물과 괴물을 씬에 배치한다.                                                                |
| 플레이어와 캐릭터 | `src/game/player/`에 점프 규칙을 둔다. `src/platform/babylon/player/`는 이동·충돌·시점, `actors/`는 공유 리그·관절 자세·모델 애니메이션을 맡는다.                                                                                                                              |
| 장비와 전투       | `src/app/equipment/weapon-types.ts`가 장비별 준비·보급·표기 규칙을 연결한다. `src/platform/babylon/equipment/`는 손에 든 도구와 발사를, `effects/`는 투사체 비행과 표면 적중을, `arena/`는 전장 총기와 목표물 표시를 맡는다. 경기 규칙은 `src/game/experiences/`에서 처리한다. |
| 조명과 렌더링     | `src/platform/babylon/lighting/`에 벽 등불·개구부 채광·그림자를, `rendering/`에 렌더러 초기화·셰이더·프레임 측정을 둔다.                                                                                                                                                       |
| 조작·설정·화면    | `src/platform/browser/`가 키·포인터 입력, 기기 설정 저장, 오디오를 맡는다. `src/ui/`에는 설정 화면·HUD·장부를, `src/ui/styles/`에는 게임 공통·타이틀 스타일을 둔다. 도입부 컷과 일러스트는 `src/intro/`에서 관리한다.                                                          |
| 본편과 설정집     | `src/game/chapter/chapter-progress.ts`가 이야기 단계·봉인·체크포인트를 소유하고 `src/platform/browser/chapter-save.ts`가 기록을 저장한다. 월드와 장부는 같은 수집물 ID와 `src/content/locales/`의 번역을 사용한다.                                                             |

공유 파일인 `src/app/main.ts`에는 시작·갱신·종료에 필요한 연결을 둔다. 장비 표시와 탄약 처리가 겹칠 때는 기존 `loaded`·`reserve` 저장값을 유지하고, 활의 화살통·시위 표기는 실제로 다음 화살을 걸었는지에 따라 계산한다.

탄환·주문·화살은 실제 궤적에서 처음 만난 표면의 피격 부위를 쓴다. 파수꾼은 스켈레톤을 따르는 머리·몸 판정 메시를 사용하고, 잉크 망령은 움직이는 가면이 머리다. 무기·충전·스킬로 몸통 피해를 정한 뒤 `src/game/combat/hit-region.ts`에서 머리 배율을 적용한다. 챕터의 잉크 그림자는 기절 규칙을 따른다.

## 플레이 HUD

전체화면이나 가로 고정을 지원하는 모바일 브라우저에서는 최상위 문서가 화면 상태를 소유한다. 메뉴와 레벨은 같은 출처의 `archive-game` 프레임에서 열어 장면을 교체한다. 모바일 DOM 검증은 이 프레임을 사용하고, 탭 주소와 전체화면 여부는 최상위 문서에서 확인한다.

챕터 목표와 전장 점수·시간은 왼쪽 위의 같은 자리를 쓴다. 미니맵은 오른쪽 위, 체력·방어구와 자세는 왼쪽 아래, 장비·탄약은 오른쪽 아래에 둔다. 화면 중앙은 조준·상호작용에 쓰고 이야기 자막은 하단 가운데에 표시한다. 짧은 화면에서는 자막이 양쪽 장비 표시 아래에 독립된 줄을 차지한다. 배치와 반응형 규칙은 `src/ui/styles/hud.css`에서 관리한다.

장비의 단축키와 현재 사용 상태를 함께 보여 주고, 상세 설명은 장부에서 열람하도록 했다. 이 구분은 오버워치의 장비 HUD와 상세 정보 화면을 참고했다. [장비 HUD](https://overwatch.blizzard.com/en-us/news/patch-notes/live/2025/10/) · [상세 정보 화면](https://overwatch.blizzard.com/en-gb/news/patch-notes/live/2025/08/)

## 레벨 데이터와 충돌 처리

- `shared/levels/`에 벽·가구의 프리팹, 배치, 치수와 개구부를 기록한다. 같은 프리팹에서 외형과 충돌체를 배치한다. 창이나 문을 수정할 때에는 이동과 시야가 실제 개구부를 통과하는지도 확인한다.
- 월드가 로딩을 끝내면 `collider-contact.ts`에서 고정 충돌체의 월드 좌표 경계를 준비한다. 문·움직이는 화물·궤짝 뚜껑처럼 자신이나 부모의 위치·회전·크기가 플레이 중 달라지는 충돌체는 해당 월드 모듈에서 `movingColliders`에 등록한다. 고정 구조물을 다시 배치할 때에는 변경이 끝난 뒤 경계를 다시 준비한다.
- 카메라와 횃불은 월드가 제공하는 공통 충돌 검사 함수를 호출한다. 경계가 겹치는 후보는 실제 표면의 삼각형으로 검사하므로 계단과 얇은 벽 형태를 보존한다. Unity나 Unreal로 이식할 때에는 레벨 데이터와 게임 상태 규칙을 가져가고, 이 호출에 대상 엔진의 충돌 검사를 연결한다.

## 성능 측정

- 개발 서버에서 `window.__FRAME_PROFILE__.start()`로 기록을 시작하고 `window.__FRAME_PROFILE__.stop()`으로 결과를 받는다. 같은 장소·시점·실제 렌더 해상도·조명 옵션에서 에셋 로딩을 마친 뒤 비교한다. 평균 FPS와 함께 프레임 시간 p95, CPU의 렌더 구간, GPU 시간, 활성 메시와 드로우 콜을 확인한다.
- 성능 HUD의 `GPU` 항목과 프레임 프로필의 `graphics.renderer`는 브라우저에서 게임을 렌더링하는 어댑터를 나타낸다. 듀얼 GPU 시스템에서 Windows의 앱별 그래픽 기본 설정을 바꿨다면 브라우저를 완전히 재시작하고 이 값을 다시 확인한다.
- 일반 플레이에서는 캔버스 버퍼를 보존하지 않고, MSAA가 꺼지면 화면으로 직접 렌더링한다. `toDataURL()`이나 다른 캔버스로의 복사로 플레이 프레임을 추출하는 검증은 `?capture=1`로 연다. 이 모드는 프레임 성능 비교에서 제외한다.
- 비용이 큰 검사 하나를 바꿀 때에는 같은 씬과 입력으로 검사 시간과 결과를 함께 비교한다. 카메라·횃불은 계단과 얇은 벽, 움직이는 문, 충돌 활성 상태가 바뀌는 경우를 확인한다.
- 발광 투사체는 `src/content/catalogs/projectile-lights.ts`의 색·범위·비행·적중·잔광 세기를 사용한다. `spell-effects.ts`가 위치와 수명을 계산하고, Babylon 연결부의 점광원 두 개를 비행과 잔광에 재사용한다. 범위와 공용 벽 가림 검사로 수신 표면을 제한하고, 착탄한 잔광은 표면을 따라간다. 조명화살이나 불화살에는 같은 형식의 광원 설정을 연결할 수 있다.

## 총기 전투 모드

메인 화면에서 데스매치, 폭탄 설치, 인질 구출, 섬멸전을 골라 고딕 투기장에 들어간다. 경기마다 권총과 800 크레딧으로 시작한다. 라운드 시작 후 25초 동안 출발 지점에서 M 또는 상점 버튼을 눌러 소총과 장착 총기의 예비탄을 구매할 수 있다. 총기는 1·2로 바꾸고 R로 재장전한다. 탄창을 비우면 예비탄이 있을 때 자동 재장전한다. 총기와 크레딧은 경기 안에서만 관리한다.

| 모드      | 승리 조건                                                              |
| --------- | ---------------------------------------------------------------------- |
| 데스매치  | 120초 안에 적 6명 처치. 쓰러지면 재출전                                |
| 폭탄 설치 | A 또는 B에 설치하고 적의 해체를 막아 폭발시킨다. 선 2승                |
| 인질 구출 | 인질에게 접근해 호송하고 출발 지점의 녹색 원까지 함께 도착한다. 선 2승 |
| 섬멸전    | 재출전 없이 적 3명을 전원 처치한다. 선 2승                             |

## 렌더러 검증

기본 렌더러는 WebGL이다. 시작 URL의 `?renderer=webgl` 또는 `?renderer=webgpu`로 백엔드를 지정하면 레벨 전환에도 유지된다. WebGPU 초기화에 실패하면 시작 화면의 ‘WebGL로 입장’으로 같은 레벨을 다시 연다. WebGPU 검증에는 localhost 또는 HTTPS에서 제공하는 실제 GPU 어댑터가 필요하다. 셰이더 변환기는 Babylon 패키지에 포함된 JS와 WASM을 게임과 같은 출처에서 읽는다.

프로덕션 빌드를 독립된 포트에 띄운 후 `./tools/renderer-acceptance.ps1 -BaseUrl http://127.0.0.1:4186/`를 실행한다. 두 백엔드에서 1280×720 데스크톱과 568×320 모바일 가로 뷰포트로 고딕 전장을 열고, 3인칭 전환·걷기 애니메이션·GPU 오류를 검사한다. 실제 백엔드, 어댑터, 해상도, 화면 캡처는 출력된 임시 폴더에 남는다. [Babylon WebGPU 지원](https://doc.babylonjs.com/setup/support/webGPU/)

Windows용 Chromium에서는 WebGPU의 고성능 GPU 선호 옵션이 무시될 수 있다. 성능 HUD와 검증 결과의 실제 어댑터 이름을 확인한다. WebGL 1 호환 경로는 Chrome을 `--disable-webgl2`로 실행해 확인한다. WebGPU 복구 경로는 일반 HTTP 호스트에서 같은 레벨로 다시 입장해 확인한다.

## 통합 검증

통합할 때는 최신 기능 브랜치에서 작업 단위 커밋을 가져오고 `npm test`, `npm run build`를 실행한다. 별도 워크트리에서 플레이를 검증할 때에는 각각의 로컬 포트와 Orca 내장 브라우저 탭을 사용한다. 같은 주소를 쓰면 다른 작업의 세이브와 키 설정까지 공유된다.

자동 검사는 `tests/unit`(게임 규칙·입력), `tests/integration`(실제 씬·충돌·광원), `tests/content`(제작 명세·배포 자산)에 둔다. `npm run check:level`은 빌드 전에 콘텐츠의 필수 검사를 실행한다. 브라우저 검증과 일회성 기록을 구분하는 기준은 [테스트 감사](ARCHITECTURE-PLAN.md#테스트-감사-기준)를 따른다.

`npm run dev`는 기본으로 `0.0.0.0`에 바인딩한다. 같은 네트워크의 다른 기기에서는 Vite가 표시하는 `Network` 주소를 연다. 포트를 지정할 때는 `npm run dev -- --port 5191`을 사용한다.
