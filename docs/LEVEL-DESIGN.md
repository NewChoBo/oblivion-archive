# 망각의 서재 · 레벨 제작 원칙

도면 JSON은 저장소 루트의 `shared/levels/`에 있다. 아래 Babylon 제작·검사 명령은 `babylon/`에서 실행한다.

## 공간 콘셉트

우주 한가운데 성 하나가 홀로 떠 있다. 플레이어가 탐험하는 서재는 그 성 안에 있다.

- **성 밖**은 거의 검은 허공에 먼 성운과 별빛만 드문드문 남긴다. 서쪽 전망탑 위에서는 은청색 성운을 바라볼 수 있고, 난간 아래로 시선을 내리면 별빛이 끊기며 깊은 어둠으로 이어진다. [스카이박스 제작 기록](../asset-sources/Art/Chapter1/CELESTIAL-SKY.md)
- **서재 안**에는 두꺼운 돌벽, 오래된 목재 서가, 기록대의 호박색 등불을 둔다. 창에서 들어오는 차가운 빛은 돌과 바닥 가장자리에 닿고, 등불은 책과 사진을 읽을 수 있는 작은 영역을 밝힌다.
- **첫 조망**은 서가 사이로 창이 일부 보이는 지점에서 시작한다. 창 가까이 다가가면 바깥을 넓게 볼 수 있게 하고, 창에서 돌아서면 기록대와 다음 통로가 시야에 들어오게 한다.
- **성곽 산책길**은 도착섬에서 굽은 석교와 쌍탑 관문을 지나 광장으로 이어진다. 광장 양편에 제본 공방과 하역 창고를 배치한다. 서쪽 성곽길의 끝이 원형 천문대다. 정면의 계단은 본관과 양옆 서고동으로 열린다.
- **서재의 사용 흔적**은 창가 벤치와 입구 벽의 기록 궤짝처럼, 사람이 어디에서 읽고 보관했는지 보여주는 가구로 남긴다. 가구 배치는 기록대와 아치 사이를 걸을 수 있는 폭을 남긴다.
- **캐릭터** 콘셉트의 서기관은 남색 후드와 상아색 가면을 쓴다. 갤러리 모델은 KayKit 리그로 이 모습을 구현했고, 플레이용 인간형의 키와 자세는 공통 Y Bot 리그에 맞춘다. [플레이용 인간형 기준](../asset-sources/Art/characters/BABYLON.md)

## 구역과 오브젝트

새 성채 원화에서 도착섬과 굽은 석교, 원형 쌍탑, 천구의 광장, 서쪽 천문대, 제본 공방, 하역 창고와 대서고 세 동을 골라 평면과 보행 종단면을 그렸다. 광장은 높이 0 m, 도착섬은 −2 m, 천문대는 +2 m, 대서고 테라스는 +4.5 m다. 도면과 씬은 같은 배치 파일의 윤곽과 높이를 사용한다. 벽등이 이어지는 긴 벽이나 바닥은 `lightTiles`의 `x`, `z`에 축별 최대 구획 길이를 미터로 지정한다. 원래 충돌체를 사용하고, 같은 구역에서 도달 범위가 겹치는 벽등을 각 렌더링 구획에 배정한다. 구획 경계에서 빛이 이어지도록 고정 광원의 슬롯을 확보하고, 휴대 횃불에는 추가 슬롯을 배정한다.

성곽의 여장은 난간을 따라 뻗는 축에 맞춰 `rampart-merlon-x` 또는 `rampart-merlon-z`를 사용한다. 난간과 여장의 두께는 0.34m로 맞추고, 덮개돌은 여장 본체 위에 놓아 맞닿은 면에서 겹치는 벽돌이 생기지 않게 한다.

## 벽에 문과 창 만들기

`bounds`로 벽 하나를 배치한 뒤 `openings`에 비울 사각형을 추가한다. 아래 벽은 X축으로 길게 뻗어 있고, 왼쪽에 바닥에서 시작하는 문 하나와 오른쪽에 창 하나가 있다.

```json
{
  "id": "reading-wall-example",
  "name": "열람실 북쪽 벽",
  "prefab": "stone-wall",
  "bounds": [
    [0, 8],
    [0, 4],
    [12, 12.25]
  ],
  "openingAxis": "x",
  "openings": [
    { "span": [1, 2.2], "height": [0, 2.25] },
    { "span": [4, 5.4], "height": [1, 2.4] }
  ]
}
```

- `bounds`는 X·Y·Z 순으로 벽의 월드 최소·최대 좌표를 지정한다. `openingAxis`는 벽이 길게 이어지는 축 `"x"` 또는 `"z"`다.
- `span`은 지정한 축의 월드 좌표 범위, `height`는 Y축의 월드 좌표 범위다. 바닥에서 시작하는 문은 `height`의 하한을 벽 하단에 맞춘다. 창은 벽 하단보다 높여 창턱을 남긴다.
- 직사각형은 벽 두께 전체를 관통한다. 여러 개가 겹치면 하나로 이어진 구멍이 된다. 벽 밖으로 나가거나 면적이 없거나 벽 전체를 없애는 입력은 오류로 처리한다.
- 문 자리에는 챕터의 `doorFrames` 키를 `frame`으로 연결한다. 남문의 뾰족아치와 북문의 반원 아치는 문틀의 안쪽 곡선을 벽 두께 끝까지 관통시킨 형상이다. 외장·내장·통행·카메라가 같은 윤곽을 따른다. 평평한 인방을 쓰는 보관실과 귀환문은 폭과 높이로 자른다. 움직이는 문짝은 독립 오브젝트다.

챕터 1의 열람실 아치와 동쪽 귀환문, 보관실 봉인문과 남쪽 빗장문에서 같은 방식을 사용한다. 남은 벽 조각만 렌더와 충돌에 등록되므로 개구부 가운데와 가장자리를 나눠 확인한다. 문짝이 있는 곳은 잠금 상태와 열린 상태에서 각각 걷고, 3인칭 카메라와 조준선이 빈 공간을 통과하는지 본다. [챕터 씬 배치](../shared/levels/chapter-1.json) · [충돌과 광선 테스트](../babylon/tests/integration/environment.test.mjs)

Unity나 Unreal로 옮길 때는 프리팹·배치 JSON과 원본 GLB를 기준으로 삼는다. 개구부를 뺀 벽 조각은 대상 엔진의 기본 박스 메시와 충돌체로 만들 수 있다. [좌표 변환과 에셋 경로](CHAPTER1.md#환경-에셋과-씬-배치)

## 광원과 그림자

- 등불과 촛불의 광원은 보이는 불꽃에서 시작한다. 실내의 간접광은 재질을 희미하게 읽을 수 있는 정도로 유지한다. 등불이 닿는 곳과 닿지 않는 곳을 같은 노출로 확인한다.
- 바깥 빛을 받는 벽은 `exteriorLight`로 빛의 방향과 범위를 적는다. 오프셋은 개구부 중심에서 바깥쪽 광원까지의 거리다. 창살·창틀·문틀의 실제 메시로 빛을 가린다. 유리는 빛을 통과시킨다. [챕터 씬 배치](../shared/levels/chapter-1.json)
- 실내외가 맞닿는 벽은 `exteriorFace`에 월드 축, 바깥쪽 면(`min` 또는 `max`), 외벽 재질을 지정할 수 있다. 렌더 메시의 바깥쪽 면은 성곽 광원을 받고 개구부 그림자를 투영한다. 벽 두께와 충돌체는 기존 벽 조각을 사용한다.
- 고정 광원의 그림자 맵은 재사용한다. 휴대 횃불은 불꽃이 움직일 때 근처 물체의 큐브 그림자 맵을 갱신한다. 불을 끄면 휴대 광원을 해제해 고정 광원의 조명 슬롯과 그림자가 같은 구성을 유지하게 한다. 렌더링에 필요한 셰이더는 초기 로딩 중 준비한다. [Babylon.js 그림자 문서](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows)
- 휴대 횃불의 불꽃과 광원은 같은 기준점을 사용한다. 가구나 벽에 다가가면 1인칭은 손과 횃불 모형을 함께 당기고, 3인칭은 캐릭터의 손을 몸쪽으로 접는다. 두 시점 모두 레벨의 충돌체를 기준으로 불꽃이 물체 안에 들어가지 않도록 한다.
- 그림자 품질의 성능 우선은 고정 광원 위주로 계산한다. 균형은 휴대 횃불에 256 픽셀 큐브 면을 쓰고, 선명은 512 픽셀 면을 쓴다. 두 설정 모두 광원 위치와 그림자 맵을 같은 프레임에 갱신하고, 각 면에 닿는 물체만 투영한다. 선명도는 해상도와 투영 범위에 영향을 받으며, 자연스러운 경계 흐림은 광원의 크기와 물체 사이 거리에 따라 달라진다. [Babylon.js 그림자 문서](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows)

## 개발 모드의 겹침 경고

`npm run dev`에서 챕터 준비가 끝나면 레벨 JSON으로 배치한 불투명 구조 메시의 표면을 한 번 검사한다. 같은 방향의 표면이 0.5mm 이내에서 면적으로 겹치면 콘솔에 Z-fighting 후보를 기록한다. 경고에는 배치 ID, 구역, 메시 이름, 월드 좌표와 해당 겹침의 면적·간격을 담는다. 같은 조합의 최초·마지막 검출 시각과 횟수는 브라우저에 저장한다.

| 콘솔 명령                          | 동작                                           |
| ---------------------------------- | ---------------------------------------------- |
| `__LEVEL_DIAGNOSTICS__.scan()`     | 현재 배치를 다시 검사한다.                     |
| `__LEVEL_DIAGNOSTICS__.history()`  | 현재 브라우저와 주소에 저장된 경고를 조회한다. |
| `__LEVEL_DIAGNOSTICS__.download()` | 경고 이력을 JSON 파일로 내려받는다.            |

`npm run check:level`은 실제 챕터 배치와 성채 생성기로 씬을 만들어 같은 방향의 구조면이 겹치면 위치와 물체 이름을 출력하고 실패한다. 난간 하부·계단참은 바닥 접촉을, 천구와 화물은 보행 충돌과 위치 갱신을 검사한다. 이 단계는 `npm run build` 전에 자동 실행된다.

장식과 병합 메시의 실제 깊이는 개발 서버에서 챕터 로딩을 마친 뒤 `tools/architecture-depth-review.js`로 확인한다. 입구·서재·회랑·성곽 등 48개 시점에서 불투명 메시를 두 순서로 그려 표면이 뒤바뀐 픽셀과 메시 쌍을 기록한다. 문틀 마감은 벽의 단면까지만 연장하고, 본관 상층 벽은 회랑 천장과 맞닿는 부분을 잘라 같은 면을 두 번 만들지 않는다.

게임에 배포하는 GLB도 텍스처 파일·내장 이미지 범위·삼각형의 인덱스와 같은 방향의 중복 면을 검사한다. 중복 면 검사는 각 모델 메시의 비압축 삼각형이 대상이다. 반투명 재질 정렬, 그림자 떨림, 서로 다른 장식 모델이 일부만 교차하는 경우는 플레이 화면에서 따로 확인한다.

월드 카메라의 near/far는 0.04 m와 145 m다. 같은 위치의 불투명 구조면은 제작할 때 하나로 정리한다. 납선 유리는 창틀 안에, 바닥이 꺾이는 곳의 난간은 연속 기단 위에 놓는다. 의도적으로 바탕에 붙는 데칼에는 재질의 `zOffset` 또는 `zOffsetUnits`를 개별 적용할 수 있다. [Babylon.js Material](https://doc.babylonjs.com/typedoc/classes/babylon.material)

## 개발 모드의 프레임 측정

콘솔에서 `__FRAME_PROFILE__.start()`로 기록을 시작하고 동선을 재생한 뒤 `__FRAME_PROFILE__.stop()`으로 결과를 본다. 프레임 간격과 이동·충돌, 캐릭터 자세, 월드·HUD, 장비 효과, 렌더 호출 시간을 ms로 기록한다. 활성 메시와 드로우 콜도 함께 기록하며, 타이머 쿼리를 지원하는 그래픽 환경에서는 GPU 시간도 나온다. 일시정지 메뉴를 측정하려면 `start({includePaused:true})`를 사용한다.

## 대서고 배치와 편집 원본

열람실의 사진부터 원부와 귀환문까지 각 단서가 무엇을 알려 주는지, 어느 선택 구역에 어떤 퍼즐을 추가할 수 있는지는 [챕터 1 퍼즐과 기믹 배치](CHAPTER-1-PUZZLES.md)에 정리했다.

차기 맵의 하역장·제본 공방·열람동은 작업자의 자세와 재료 이동부터 설계한다. 기물마다 플레이어의 첫 시선, 실물 고증, 재질과 밝기, 이동·상호작용에서 생길 문제를 검토한다. 편집 원본은 `asset-sources/Art/Chapter1/work-layout.json`이다. `python tools/draw-work-layout.py`로 현행 외곽선에 제안한 배치를 겹쳐 그리고 화물·통로의 여유를 검사한다. [검토 결정과 도면·원화](art/chapter-1/work-review.html)

제작할 때에는 먼저 성채 평면, 지상층 동선, 계단 단면, 정면 입면, 가구 배치의 다섯 도면을 확인한다. 제작표에는 각 구역의 부품, 고정 수량, 가구 기준점과 충돌 치수, 재질 견본이 있다. [성채 제작 도면](art/chapter-1/construction.html)

외곽선을 바꾸면 `python tools/draw-fortress-plan.py`로 배치도를 갱신한다. 도면과 실제 포장·축대·난간이 같은 측량점을 읽는다. 난간은 외곽선에서 안쪽으로 0.36 m 두께를 가지며, 모서리의 접선 원호는 기본 반경 1.10 m다. 석재의 마감은 상단 15 mm 모따기다. 성채의 두 계단은 각각 11단과 14단이다. 보행용 경사면을 인접한 두 디딤면 높이의 중간에서 잘라 돌계단을 만든다. 굽은 난간 근처에서도 발밑 충돌면과 디딤면 사이의 수직 거리가 한 단 높이의 절반 이내다.

가구 원점, 색, 시공 단면, 구역별 부품은 `shared/levels/citadel-construction.json`에서 편집하고 `python tools/draw-citadel-details.py`로 입면·단면과 배치표를 갱신한다. `npm run check:level`이 실제 생성된 외부 부품의 종류와 지정 수량, 가구의 위치·높이, 계단 접합을 검사한다. 겹친 구조면은 깊이 우선순위로 덮으면 시점과 거리에서 다시 드러날 수 있다. 평면을 중복 생성하지 않고 개구부·바닥·연결부의 경계를 나누는 것이 이 맵의 제작 기준이다.

본관과 양쪽 날개의 크기·높이는 `shared/levels/fortress-exterior.json`, 지상층의 벽·문·가구는 `shared/levels/chapter-1.json`에서 바꾼다. 배치의 `heading`은 보이는 부품과 충돌체를 함께 회전한다. 수정한 뒤 `python tools/draw-library-route.py`를 실행하면 지상층 도면에 새 벽과 개구부가 반영된다.

## 언리얼의 문과 창 제작 사례

Epic의 _Geometry Editing Content Examples_ 1.6은 벽을 더한 뒤 문·창 부피를 빼서 집을 만든다. 빼기 브러시를 먼저 적용하면 이후에 더한 벽이 구멍을 다시 채운다. [Example House, 1.6](https://dev.epicgames.com/documentation/en-us/unreal-engine/geometry-editing-content-examples?application_version=4.27) · [Geometry Brush Actors](https://dev.epicgames.com/documentation/unreal-engine/geometry-brush-actors-in-unreal-engine)

*Lyra*의 `B_Tool_AdvancedWindow`는 직각 외곽 안에서 개구부를 움직이고 안쪽 모서리를 둥글게 조정한다. 제작자는 결과를 정적 메시로 굽고 원본 도구를 보관해 다시 편집한다. Modeling Mode의 Boolean에서도 벽을 A, 문틀의 빈 부피를 B로 잡으면 A−B가 남는다. [Lyra Geometry Tools](https://dev.epicgames.com/documentation/unreal-engine/lyra-geometry-tools-in-unreal-engine) · [Boolean Tool](https://dev.epicgames.com/documentation/unreal-engine/boolean-tool-in-unreal-engine)

이 챕터에서는 벽 두께가 일정하므로 문틀 윤곽을 관통시켜 남는 면을 로딩 때 한 번 삼각형으로 만든다. 문 개폐는 문짝의 상태만 바꾼다. 남문은 바깥 돌과 안쪽 회벽의 경계를 나누고, 아치 꼭대기·양옆 문설주·중앙 통과를 양쪽에서 광선과 카메라 충돌로 검사한다.
