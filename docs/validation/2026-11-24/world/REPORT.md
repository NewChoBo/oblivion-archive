# 성채 건축·생활 배치 검증

기준 `be31dcf` → 구현 커밋 `79ae70d`. 이 기록은 이 작업 트리의 건축·조명 변경에 대한 것으로, 다른 팀의 조작·무기·도입부·RPG 변경을 포함하지 않는다. Push는 하지 않았다.

## 구현

- 양익 아치 전후 면을 정면 벽의 실제 절단면 `Z=36.02..36.38`에 맞췄다. 첨두 곡선은 벽 개구부·아치·본관 별창에 같은 30분할 기준을 쓴다. 본관 별창 벽은 앞뒤 면과 절단면을 갖고 창 아치 뒤끝은 벽 안에 물린다. 별도 몰딩으로 덮지 않았다.
- 8개 봉화의 받침은 난간 위에서 포장으로 옮겼다. 중심은 난간 안쪽 면에서 0.31 m, 받침 반경 0.27 m이며 하단 0.16 m를 포장 안에 넣어 경사에서도 발이 뜨지 않는다. 받침 9점씩의 지지 광선 검사를 통과했다.
- 하늘 반사광 0.12, 외부 방향광 0.19, 실내 반사광 0.13, 외벽 반사 프로브 0.62. 문·창으로 들어오는 밤빛을 기존의 18%로 낮추고 봉화 주변에 따뜻한 점광원을 뒀다. 고정 실내 광원은 그대로 문·벽에 가려진다.
- 성 전체의 여장을 한 메시로 합치면 8개 봉화를 동시에 예약해 WebGL uniform block 한도를 넘겼다. 9 m 공간별로 메시를 합치고 봉화를 근처 외벽에 한정했다. 최종 빌드에서 PBR 최대 조명 슬롯은 8, 시작 준비는 정상 완료됐다.
- `citadel-construction.json.workLayout`이 기존 작업 도면 원본을 지정하고 `src/citadel-layout.js`가 게임·도면·검사·배치표에 공통 해석 결과를 제공한다. 도면 생성기가 별도 치수를 복사하지 않는다.
- 하역기는 (30.5, 8.2) 고정 기초와 회전 상부를 분리했다. 3.2초 인양 → 3.6초 90° 선회 → 2초 하강 후 (30.5, 12.8)의 포장에 착지한다. 줄·도르래·화물 충돌체가 함께 움직인다. 동벽 인계문은 남쪽으로 주차하는 한 장의 미닫이다. 북쪽 여유는 0.275 m뿐이므로 북쪽으로 미는 문짝은 쓰지 않았다.
- 공방은 박공지붕·0.76 m 봉철 작업대·걸상·압착기·수평 접지 선반, 열람동은 0.76 m 상판·0.44 m 좌면·0.83 m 등받이로 바꿨다.
- 봉인 받침 3개를 북쪽 0.46 m 옮겼다. 표식·충돌체는 같은 배치에서 나오며 진행 앵커도 그 좌표에서 계산한다. 본관 사진·원부·빗장 위치와 진행 조건은 유지했다.

## 한계

Orca의 pointer lock은 `WrongDocumentError`로 거절돼 자유 시점을 사용했다. 원래의 일괄 완주 스크립트는 native key-up 지연으로 문 진입·받침 접근·사진 귀환에서 목표를 지나쳤다. 실제 입력으로 보정하고 체크포인트를 이어서 엔딩에 도달했으며 좌표·진행 setter는 쓰지 않았다. 새 받침 접근 경로를 스크립트에 반영했지만 수정된 전체 스크립트의 처음부터 끝까지 무중단 실행을 별도로 주장하지 않는다.

하역 동작의 전 시간대 접합·복구·통과는 자동 기하/충돌 검사로 확인했고 실제 플레이 후 착지도 확인했다. 인양 중 화물 탑승, 좌우 어깨 시점에서의 전체 하역 애니메이션, 인양 중 메뉴 재도전의 실제 입력 조합은 별도 검증하지 않았다. 하역 인물과 창고 안으로 나르는 애니메이션은 이번 구현에 없다.
