# Unity 챕터 1 플레이 검증

Orca 내장 브라우저의 독립 탭에서 한국어 시작 화면부터 사진 복원 엔딩까지 진행했다. WASD 이동, 마우스 오른쪽 드래그 시점 조작, E 조사, Esc와 화면 버튼을 사용했다. `?inspect=1`로 관측한 위치와 단계, 브라우저 저장값, 두 Web 빌드의 SHA-256은 검증 기록에 남겼다. [플레이 기록](walkthrough.json)

| 구간 | 실제 입력으로 확인한 결과 |
| --- | --- |
| 도입부와 사진 | 일반 시작 메뉴에서 별빛 독백 일러스트가 열렸다. Esc로 열람실에 입장하고 사진 앞에서 E를 누르자 첫 체크포인트가 생겼다. [독백](prologue.webp) · [사진 조사](faded-photo.webp) |
| 회랑과 재도전 | 기록대를 돌아 북쪽 아치를 통과했다. 벽화에서 등불·깃·물결을 읽은 뒤 잉크 그림자에게 붙잡혀 체력이 0이 됐다. 재도전 버튼을 누르자 X 1.70, Z 10.30에서 벽화 기록을 가진 채 다시 시작했다. [벽화](mural.webp) · [패배](shadow-defeat.webp) |
| 환경 퍼즐 | 은빛 경계를 넘어 초기 상태인 물결 세 개로 문을 조사하면 잠긴 상태를 유지했다. 왼쪽 받침을 한 번, 가운데 받침을 두 번 돌린 뒤 다시 조사하자 문이 올라갔다. 봉인문을 지나 실제 보관실 내부로 걸어갔다. [봉인 해제](vault.webp) |
| 원부와 귀환 | 원부에서 이안의 이름을 알아냈다. 보관실에서 사망한 뒤 저장된 단계에서 재도전해 남쪽 빗장을 열었다. 귀환로 북벽의 지도를 수집하고 열람실 옆문을 지나 처음의 기록대로 돌아왔다. |
| 엔딩과 이어하기 | 사진에 이름을 적어 복원 엔딩을 열었다. 갱신된 빌드로 페이지를 다시 연 뒤 시작 메뉴에서 이어하기를 선택하자 엔딩으로 돌아왔다. 해결한 봉인, 벽화 단서, 귀환로 지도도 남아 있었다. [복원된 사진](restoration.webp) |
| 성채와 추락 | 갱신된 빌드를 별도 저장 주소에서 새로 시작했다. 열람실 남문, 대계단, 천구의 광장, 쌍탑 관문을 걸어서 지나 굽은 석교에서 성채를 촬영했다. 부두 서쪽 열린 가장자리로 걸어 나가 Y −14.10m에서 추락 패배 화면을 확인했다. 사진 조사 전 재도전은 처음 열람실로 연결됐다. [대계단에서 본 광장](courtyard.webp) · [석교에서 본 성채](bridge.webp) · [추락](void.webp) |

처음부터 엔딩까지 진행한 빌드의 WebAssembly 해시는 `ad7570fd…`이다. 이어하기와 성채 보행에 사용한 다음 빌드의 해시는 `cc9252e6…`이다. 후자의 전체 챕터 재완주, 무기별 그림자 경직 시간, 여덟 기록물 전체 수집은 이번 실입력 검증 범위에 포함하지 않았다.

기존 Babylon 체크포인트 형식의 단계 1~5를 Unity 저장 코드로 읽고 다시 썼다. 단계, 세 봉인 값, 벽화 단서가 일치했다. 잘못된 형식 11건이 새 게임으로 처리되고, 체크포인트를 지워도 수집 기록이 남는 것도 별도 C# 검사로 확인했다.

도입부 두 컷은 원본의 `src/intro/art/night-watch.webp`, `erased-name.webp`에서 가져왔다. 복원 사진 원본은 `asset-sources/Art/Chapter1/archive-photo-restored.webp`다. Unity용 JPG는 원본 치수에서 Pillow의 RGB 변환과 `quality=91, optimize=True`로 생성했다. 세 파일 모두 이 설정으로 같은 바이트를 재현했다.
